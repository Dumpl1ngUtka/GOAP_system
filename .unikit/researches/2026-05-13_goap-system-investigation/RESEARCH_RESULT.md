## Тема
Анализ текущей реализации GOAP (Goal-Oriented Action Planning) для юнитов нижнего уровня (`AIAgent`) и поиск причин некорректного поведения (игнорирование целей, "замирание" на месте).

## Контекст
Пользователь сообщил, что юниты делают несколько шагов патрулирования, а затем останавливаются и перестают реагировать на окружение. Также они игнорируют большинство целей (атака, сбор ресурсов и т.д.), если им не отдан прямой приказ.

## Выявленные проблемы

### 1. Ошибка "Пустого Желаемого Состояния"
В классах целей (например, `KillEnemyGoal.cs`) метод `GetDesiredState()` возвращает пустой список условий, если цель не была принудительно назначена командиром (`_forcedTarget == null`).
- **Причина**: Планировщик интерпретирует пустое состояние как "уже достигнутое" (heuristic = 0).
- **Результат**: Агент считает, что ему ничего не нужно делать, и игнорирует цель, даже если у нее высокий приоритет.

### 2. Отсутствие прерываемости (Non-Reactive AI)
В `AIAgent.Update` выполнение текущего действия блокирует весь процесс переосмысления целей:
```csharp
if (_currentAction != null) {
    bool isComplete = _currentAction.Perform(Time.deltaTime);
    if (isComplete) { ... }
    else { return; } // Блокировка
}
```
- **Результат**: Если юнит начал патрулирование, он не заметит врага, пока не дойдет до точки. Если он застрял — он будет стоять вечно.

### 3. Проблема "Застрявших действий"
`PatrolAction` и другие действия движения зависят от `AgentMover.IsMoving`. Если юнит упирается в препятствие, он продолжает "пытаться" идти, действие никогда не завершается.
- **Результат**: В сочетании с проблемой №2, юнит превращается в "зомби".

### 4. Ограниченность поиска целей в Планировщике
`AIPlanner.Plan` ищет цели только среди `null` и объектов, явно указанных в `Goal`. Он не умеет самостоятельно выбирать подходящие цели из базы знаний (KnowledgeBase) для применения стратегий (например, выбрать ближайшего врага для `AttackAction`).

## Предложенные решения

### Краткосрочные исправления
1. **Fix `KillEnemyGoal`**: Сохранять найденную цель в поле класса во время `GetPriority`, чтобы `GetDesiredState` мог ее использовать.
2. **Fix `AIAgent.Update`**: Добавить логику переоценки целей даже во время выполнения действия. Если приоритет новой цели значительно выше текущей — прерывать план.
3. **Stuck Detection**: Добавить в `AgentMover` или `ActionBase` тайм-аут выполнения.

### Архитектурные улучшения
1. **Reactive GOAP**: Реализовать механизм прерывания (Abortion) планов.
2. **Dynamic Target Discovery**: Обновить `AIPlanner`, чтобы он собирал все доступные объекты из `KnowledgeBase` как потенциальные цели для действий.
3. **Common Base for Targeting Goals**: Создать базовый класс для целей, требующих поиска объекта, чтобы избежать дублирования ошибок с пустым состоянием.

## Заключение
Текущая система имеет прочный фундамент, но страдает от нескольких логических "петель" и отсутствия реактивности. Исправление вышеуказанных проблем позволит агентам действовать автономно и адекватно реагировать на угрозы.
